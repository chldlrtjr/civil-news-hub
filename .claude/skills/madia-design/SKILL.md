# Madia Design(마디아 디자인) 웹 UI 디자인 스킬

> **이 프로젝트(Civil News Hub)에서는 아래 규칙이 이 문서보다 우선한다.**
> 1. 웹 페이지 어디에도 이모지를 쓰지 않는다. 아이콘은 SVG, 상태는 텍스트와 색 배지로 표현한다.
> 2. 다크 모드를 유지한다. 이 문서의 팔레트는 라이트 기준이므로 토큰을 바꿀 때는 `:root` 다크 블록 2곳(`prefers-color-scheme`, `[data-theme="dark"]`)도 같이 바꾼다.
> 3. 분야 색(`--c-road`, `--c-water`, `--c-tunnel`, `--c-smart`)과 D-day 경고색은 정보 구분용이다. [충돌 9]의 대시보드 예외에 해당하므로 무채색화하지 않는다.
> 4. 이 사이트는 1920px 마케팅 랜딩이 아니라 정보 밀도가 높은 대시보드·피드다. 섹션 `120px`, 푸터 `170px` 같은 랜딩용 대형 여백은 그대로 옮기지 않는다.
> 5. PC(`#ca`)와 모바일(`#m`) 레이아웃은 별개 DOM으로 나뉘어 있다. 7.3(동일 소스 반응형)을 이유로 구조를 합치지 않는다. 토큰과 컴포넌트 규칙만 각각에 적용한다.
> 6. 기능, 데이터 로직, 접근성(포커스 링, `prefers-reduced-motion`)은 디자인 변경으로 건드리지 않는다.

> **통합 출처**
> - **원칙(A):** Madia Design `UXUI 디자인` 실무 강의 19편 (`[A-1]` ~ `[A-19]`)
> - **실제 수치(B):** Madia Design `무작정 따라하기` 31편 중 순수 웹 화면 5편 (`[B-#09]`, `[B-#16]`, `[B-#17]`, `[B-#18]`, `[B-#20]`) 정밀 집계 + 모바일 17편 프레임 참고
>
> **AI 코딩 에이전트 적용 규칙**
> 1. 각 섹션의 원칙은 **여러 영상에서 반복 검증된 규칙을 최상단**에 우선 배치하며, 근거 빈도(`[A n편 · B m/5편]`)와 **B의 실제 사용 수치**를 예시값으로 병기한다.
> 2. **단 1편에서만 등장한 규칙·수치**는 본문에서 제외하고 **`10. 약한 근거`** 섹션으로 분리한다.
> 3. **원칙과 실측 수치가 어긋나거나 영상끼리 모순되는 항목**은 삭제하지 않고 **`9. 충돌`** 섹션에 모아 맥락별 판단 기준을 제시한다.
> 4. 신규 웹 UI 작성·수정 시 별도 지정이 없으면 최신 Figma 웹 5편(`B`)에서 100% 수렴한 기본 토큰(`Pretendard`, `line-height: 1.4`, `letter-spacing: -0.025em`, `#111111`, `1920px` 기준 `8px` 리듬, Flex/Grid 가변 구조)을 우선 채택한다.

## 1. 핵심 철학

### 1.1 초기 기준·컨셉·논리적 근거("왜") 선확정 및 전 화면 일관 유지 `[A 11편 · B 5/5편]`
- 작업 착수 전에 해상도, 그리드, 서체·행간·자간, 모서리 컨셉(직각 vs 라운드), 컬러 정책을 먼저 확정하고 첫 화면부터 끝 화면·파생 페이지·아이콘까지 임의로 바꾸지 않는다.
- 모든 크기·굵기·색상·간격·그림자 결정에는 "느낌상/예뻐 보여서"가 아니라 타인에게 설명할 수 있는 명확한 기능적·시각적 목적("왜")을 둔다.
  - **B 실제 수치 예시값:**
    - 전 영역 타이포 토큰 고정: `Pretendard` (`5/5편`), `line-height: 140%` · `letter-spacing: -2.5%` 전 사이즈 동일 적용 (`4/5편`: `#16, #17, #18, #20`)
    - 모서리 컨셉 일관 유지: 라운드 채택 웹(`#16, #20`)은 `8 / 12 / 16px` 계층으로 통일, 직각 미니멀 웹(`#17, #18`)은 끝까지 직각·라인 톤 유지
  - *(A 실전 참고: 로그인 9종 파생 화면 전체에 카드 `460px`, 패딩 `48px/40px`, 내부 `364px` 규격 100% 복제 `[A-11]`)*

### 1.2 가변·반응형 구조 우선 및 개발·퍼블리싱 공수 고려 `[A 7편 · B 3/5편]`
- 해상도나 텍스트 길이가 바뀔 때 깨지지 않도록 고정 좌표·임의 도형 대신 컨테이너 기반 가변 레이아웃(CSS Flexbox/Grid, `width: 100%`, `width: fit-content`, `overflow: hidden`)으로 설계한다.
- 디자이너의 시각적 욕심만으로 브레이크포인트·뷰 모드별 변수를 남발하지 않고, 공통 CSS 규칙과 최소 변경 원칙으로 개발 공수를 통제한다.
  - **B 실제 수치 예시값:**
    - 반응형 구조 조합 (`3/5편`: `#17 21:22`, `#18 12:57~13:52`, `#20 23:15~26:30`): `Fill container`(텍스트·프로필), `Hug`(버튼·탭 언더라인), `Clip content`(카드 모서리 클리핑), `Constraints`(Left/Right/Bottom)
    - 해상도 가변 시 폰트·행간(`140%`)·자간(`-2.5%`) 고정 유지 (`#18`, `[A-14][A-16]`)

### 1.3 실제 크기·다중 해상도·실기기 프리뷰 최종 검수 필수 `[A 5편 · B 1/5편]`
- 디자인 툴 캔버스의 축소 화면만 믿지 말고, 실제 브라우저 뷰포트 리사이징·프로토타입 `Play` 모드·모바일 실기기에서 체감 폰트 크기, 첫 화면 노출 범위, 겹침·깨짐을 검증하고 수치를 보정한다.
  - **B 실제 수치 예시값:**
    - 반응형 검수 뷰포트 구간: `1280 / 1420 / 1920 / 2560 / 3840px` 직접 조절하며 겹침·비율 검증 (`#18 01:16, 33:28~34:03`)
  - *(A 실전 참고: `Play` 모드 검수 후 빌보드 폭 `1600→1580px`, 첫 화면 금액 걸림 보정 `40→32px` `[A-2][A-6]`)*

### 1.4 선 구조·러프 배치 → 후 디테일·이미지 삽입·최종 보정 `[A 5편 · B 3/5편]`
- 처음부터 미세한 장식에 매달리지 않는다. 캔버스·마진 가이드 → 큰 섹션 덩어리·누락 없는 텍스트 구조 → 1개 기준 컴포넌트 완성 후 복제 → 실제 이미지 삽입 → 딤드·간격·라인 최종 보정 순으로 진행한다.
  - **B 실제 수치 예시값:**
    - GNB 영역을 임시 배경으로 먼저 구획 확인한 뒤 최종 단계에서 투명 배경 통합 (`3/5편`: `#09 02:01`, `#17 01:42`, `#20 01:37`)
    - 실제 이미지 삽입 후 가독성 딤드(`#000000 20%`, `#17 04:22`·`#18 21:21`) 및 국소 그라디언트(`#111111 0%→50%`, `#20 11:47~13:16`) 후속 조율 (`3/5편`)

### 1.5 실무 예외 케이스(Full Case / 상태 분기) 누락 없는 설계 `[A 4편 · B 모바일 다수·웹 #16/#20]`
- 이상적인 정상 화면 1장만 구현하지 않는다. 오류 상태, 미선택/선택 후 변화, 1줄/2줄 텍스트 줄바꿈, 긴 숫자 자릿수, 필터 선택 칩 줄바꿈·초기화, 무료/유료 기능 유무 등 실무 분기를 모두 설계한다.
  - **B 실제 수치 예시값:**
    - 대시보드 필터·검색·진행바 상태(`#16`), 요금제 무료(미지원 `X` + `#767676`) vs 유료 강조 및 FAQ 펼침/접힘 카드(`W 940px`, 토글 `52×52px`, `#20`)
  - *(A 실전 참고: 옵션 미선택/선택 후 2케이스 `[A-6]`, 로그인 오류·보안문자 등 9종 분기 `[A-11]`, 가격 9자리 `999,999,999` 검증·2줄 칩 `[A-12]`)*

### 1.6 해외 시각 시안(Dribbble/Pinterest/Behance) 맹목적 모방 금지 `[A 4편]`
- 축소 썸네일로만 오밀조밀해 보이는 해외 시안의 작은 본문, 푸터 생략, 감에 의존한 아이콘 크기를 실무 기준으로 삼지 않는다. 실제 운영 중인 대형 서비스(네이버·커머스 등)의 가독성과 정보 위계를 기준으로 검증한다.
  - **B 실제 수치 예시값:**
    - 웹 기본 본문 **`16px`** (`4/5편`), 최소 소형 본문·배지 **`14px`** (`4/5편`), 웹 접근성 명도 대비를 확보한 보조 텍스트 **`#767676`** (`3/5편`: `#16, #17, #20`)

## 2. 레이아웃

### 2.1 `8px` 기반 리듬 간격 체계 (`8 · 12 · 16 · 20 · 24 · 32 · 40 · 48px`) `[A 10편 · B 5/5편]`
- 화면 전체에 4/8px 배수 기반의 반복 간격 계층을 고정 적용해 일관된 시각 리듬을 유지한다. 임의의 홀수·불규칙 간격을 섞지 않는다.
  - **B 실제 수치 예시값:**
    - **5/5편 최빈 간격:** `24px`(카드 패딩, 탭·아이콘·타임라인·FAQ 간격), `32px`(카드 간 gap, GNB 마진/메뉴, 본문-버튼 간격), `40px`(섹션 타이틀-콘텐츠, 상단/좌측 주요 여백)
    - **4/5편 핵심 간격:** `12px`(타이틀-본문, 카드/버튼/아이콘 소간격), `16px`(아이콘-텍스트, 타이틀-본문, 리스트/필터 간격), `20px`(카드-타이틀, 탭/아이콘 내부 여백), `48px`(GNB 메뉴 간격, 좌우 외곽 마진, 블록 구분), `70px`(GNB-히어로 상단, 로고-메뉴, 블록 가로 간격)
    - **3/5편 소그룹 간격:** `8px`(버튼 간격, 아이콘-텍스트, 질문-답변 소그룹)
    - **2/5편 보조 간격:** 밀착 `2px / 4px / 6px`, 대형 구간 `100px / 120px / 200px`

### 2.2 PC 기준 캔버스 `1920px` + 중앙 유효 컨테이너(`1280px` / `1320px`) `[A 6편 · B 5/5편]`
- 데스크탑 웹은 `1920px` 가로폭(세로 유동)을 기준으로 작업하되, 저해상도 모니터를 고려해 핵심 콘텐츠를 중앙 `1280px` 또는 `1320px` 유효 영역 안에 정렬한다. (※ 12컬럼 `40px` 거터 원칙과 실전 카드 간격·`1420px` 컨테이너 차이는 [충돌 1](#9-충돌-conflicts) 참조)
  - **B 실제 수치 예시값:**
    - PC 데스크탑 기준 가로폭: **`1920px`** (`5/5편`: `#09, #16, #17, #18, #20`)
    - 중앙 콘텐츠 컨테이너 최대폭: **`1320px`** (`#17 08:24`, 좌우 여백 각 `300px` — A `[1][2][6][10]`의 `1320px` 12컬럼 외곽과 일치)
    - 풀블리드 GNB 좌우 외곽 마진: **`32px`** (`2/5편`: `#16, #17`) 또는 **`48px`** (`2/5편`: `#18, #20`)

### 2.3 섹션 간 수직 여백 `120px` · 본문~푸터 간격 `170px` 고정 `[A 4편 · B 2/5편]`
- 긴 스크롤 웹페이지에서 섹션(코너) 사이는 `120px`, 본문 최하단에서 푸터 사이는 `170px`로 통일해 전 페이지 스크롤 호흡을 일정하게 유지한다.
  - **B 실제 수치 예시값:**
    - 섹션 간 대형 수직 여백: **`120px`** (`2/5편`: `#17 11:59`, `#20 18:52` — A `[2][6]` `120px`과 일치)
    - 본문 최하단~푸터 간격: **`170px`** (`#20 39:29` — A `[2][6][11]` 전 페이지 `170px`과 일치, 합산 4편 반복)
    - 대형 보조 여백: `100px` (`2/5편`: `#09, #20`), `200px` (`2/5편`: `#09, #18`)

### 2.4 절제된 `1px` 구분선 활용 및 중복·끝단 불필요 라인 제거 `[A 10편 · B 3/5편]`
- PC·`@1x` 웹에서 섹션·행·셀·카드 경계에 얇은 `1px` 라인을 활용하되, 헤더 이중 라인이나 리스트 최하단·그리드 우측 끝단의 불필요한 외곽 라인은 반드시 제거한다. (※ `@2x` 모바일 `1px` 금지 및 상향 그림자 대체는 [충돌 15](#9-충돌-conflicts) 참조)
  - **B 실제 수치 예시값:**
    - PC 웹 `1px` 라인·스트로크 색상: `#111111` (반응형 그리드 셀, `#18 02:52`), `#E5E5EC` (보조 버튼·로고카드·배지·요금제 박스, `#20 05:13`), `#C7C7D0`·`#C9C9D9` (타임라인·필터 구분선, `#16`), `#C4C4C4` (비활성 탭 보더, `#09`)
    - 끝단 라인 제거: 그리드 마지막 열 우측 스트로크 `0` 처리 (`#18 04:37`) — A `[10]` GNB 이중선 제거, `[14]` 리스트 최하단 행 구분선 삭제와 동일 원칙

### 2.5 근접성·묶음(그룹핑) 기반 여백 위계 `[A 4편 · B 3/5편]`
- 관련 정보끼리는 간격을 좁혀 한 덩어리로 묶고, 다른 그룹과의 간격은 내부 간격보다 확실히 넓혀 소속 경계를 명확히 한다. 위·아래 어느 쪽에 속하는지 모호한 균등 여백 배치를 피한다.
  - **B 실제 수치 예시값:**
    - 밀착 소그룹: 시간-본문 `6→2px` (`#09 06:44`), 매거진 타이틀-본문 `16→4px` (`#17 20:36`), 질문-답변 `8px` (`#20 36:57`)
    - 타이틀-본문 `12~16px` (`4/5편`), 섹션 타이틀-콘텐츠 최소 `20px` 이상 (`#17 11:49`) → 주력 `40px` (`5/5편`)

### 2.6 1개 기준 모듈 선완성 후 복제 확장 `[A 3편 · B 4/5편]`
- 반복 카드·리스트·메뉴 행은 첫 1개 컴포넌트의 패딩·텍스트 줄바꿈·클리핑을 완전히 확정한 뒤 복제해 규격 이탈을 방지한다.
  - **B 실제 수치 예시값:**

## 9. 충돌 (Conflicts)

원칙(`A`)과 실제 사용 수치(`A` 실전 · `B` 웹 5편)가 어긋나거나, 영상끼리 기준이 충돌하는 16개 항목을 삭제하지 않고 전수 기록한다. 각 항목 하단의 **에이전트 판단 기준**으로 프로젝트 맥락에 맞게 선택한다.

### 충돌 1. 12컬럼 `40px` 거터 원칙 vs 실전 카드 간격(`8~10px` / `24~32px`) 및 `1420px` 확장 `[원칙 vs 실측]`
- **A 원칙 (`[A-1][A-10]`):** `1320px` 12컬럼(`20/70/20`, 유효 `1280px`) 표준 거터는 `40px`이며, `20px` 거터도 너무 좁다고 경고.
- **A 실측 (`[A-2][A-6][A-14]`):** 동일 `1280px` 커머스 리스트 실제 카드 간격은 `0~10px`(4열 `8px`, 3/5열 `10px`, 와이드 `1800px`은 `20px`).
- **B 웹 5편 실측 (`[#16][#17][#18][#20]`):** 다중 12컬럼 그리드 대신 가이드·Auto Layout 등분을 사용하며, 카드 간격은 **`32px` / `24px`**(`5/5편`)이 주류. 중앙 컨테이너도 `1320px`(`#17`) 외에 **`1420px`**(`#20`)까지 확장.
- **에이전트 판단 기준:** 외곽 컨테이너는 `1280~1320px`(와이드 SaaS는 `1420px`)로 잡되, 내부 카드 간격은 일반 웹/SaaS `24~32px`, 썸네일 밀집 커머스 `8~16px`로 적용한다.

### 충돌 2. PC 해상도 변화 시 본문 폰트: "비례 확대" vs "전 구간 고정" `[규칙 간 충돌]`
- **측 A (`[A-4]`):** `1320px`에서 본문 `14px`라면 `1920/2560px`에서는 `16~18px`로 키워 볼륨 밸런스를 맞춰야 함.
- **측 B (`[A-14][A-16]`, `[B-#18]`):** `1280~3840px` 구간에서는 개발 공수와 일관성을 위해 **폰트·행간·자간·여백을 고정**하고 이미지·컨테이너만 가변 대응.
- **에이전트 판단 기준:** 일반 웹·SaaS·커머스 기본값은 **측 B(고정, 본문 `16px`)**를 채택하고, 에디토리얼 풀와이드 사이트에서 별도 요구가 있을 때만 측 A를 적용한다.

### 충돌 3. PC GNB 구조·높이·배경: 2단 `146px` 화이트+`1px` 선 (A) vs 1단 `80px`/`48px` 투명 (B) `[A vs B 충돌]`
- **측 A (`[A-2][A-10]`):** 커머스 PC GNB는 상단 메인 바 `90px`(검색창 `460×44px`) + 하단 카테고리 바 `56px` = 총 `146px`, 화이트 배경 + 하단 `1px` 그레이 구분선.

- **원칙 (`[A-18][A-19]`):** `@2x`에서는 홀수·소수점·`1px` 선 절대 불가(최소 `2px`), 흰 하단 독바는 상단 실선 대신 상향 그림자(`Y:-10, Blur:20`) 또는 반투명 `90~95%` 선호.
- **실측 충돌:** `[A-19]` 독바 라벨 행간 `29px`, `[A-18]` 초기 카드 `233px`·아이콘 `29px`·자간 `-75`, `[A-15]` 아코디언 `569px` 등 홀수 등장; 반면 PC/`@1x`(`[A-2][6][10][16]`, `[B-#18][#20]`)는 `1px` 구분선을 기본 사용.
- **에이전트 판단 기준:** 웹 CSS(`@1x`)에서는 `1px` 구분선을 정상 사용하되, 좌표·간격·크기는 소수점 없는 정수(`4/8px` 배수)로 맞추고, 모바일 하단 고정 바는 은은한 상향 그림자나 반투명 글래스를 우선 검토한다.

### 충돌 16. 동일 커머스 띠배너 규격 편차 및 로그인 GNB 유무 `[수치·규칙 간 편차]`
- **띠배너:** `[A-2]` 메인 띠배너 `H 200px`에 타이틀 `26px` vs `[A-6]` 상품상세 띠배너 `H 140px`에 타이틀 `28px`(높이는 줄었는데 폰트는 커짐).

- **에이전트 판단 기준:** 띠배너 높이와 타이틀 크기는 비례시켜 통일하고, 로그인·인증 같은 단일 과업 페이지는 집중도를 위해 간소화/생략 헤더를 허용한다.
