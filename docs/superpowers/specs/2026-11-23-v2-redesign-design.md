# Civil News Hub v2 재디자인 설계

작성일: 2026-11-23 · 상태: 구현 완료, **2026-11-23 사용자 결정으로 v2가 기본 주소(`/`, `index.html`)가 됨.** 예전 사이트는 `old.html`에 보관하고, 예전 `/v2.html` 주소는 `/`로 넘겨준다.

## 1. 의도와 이유

- 지금 사이트(`index.html`)는 **모든 페이지에서 한 화면에 들어오는 정보가 너무 많아** 보기 불편하다. (사용자)
- **홈은 "나에게 중요한 정보"를 주는 곳**이어야 한다. (사용자)
- 다듬어 둔 지금 `index.html`은 **그대로 두고**, 마디아 디자인 기준(`.claude/skills/madia-design/SKILL.md`)으로 **새 디자인을 따로** 만든다. (사용자)
- 홈 구조는 레퍼런스를 조사해서 Claude가 짜기로 했고, 사용자는 시안 중 **A안(할 일 목록형)**을 골랐다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 새 페이지 `v2.html` 하나에 홈, 뉴스, 공모전, 채용, 전북대, 마이 6개 탭을 실제 데이터로 동작하게 만든다.
- 홈은 "오늘 챙길 것 → 내 관심 분야 새 소식 → 오늘의 토목 뉴스 3줄" 순서로 구성한다.
- 모든 탭에 "덜어내기" 규칙(4장)을 적용한다.

**비목표**
- `index.html`, `contests.html`, `jobs.html`, `mobile.html`의 수정. 지금 사이트는 그대로 운영한다.
- 수집기(Python), 데이터 번들 형식, jcloud 서버의 변경.
- 관심 분야를 계정(Supabase)에 저장하는 일. 시안을 확인한 뒤 따로 진행한다.
- v2를 기본 주소로 교체하는 일. 비교해 본 뒤 사용자가 결정한다.

**실패 조건 (동작은 해도 실패로 본다)**
- 첫 화면에 여전히 목록이 셋 이상 펼쳐져 있거나 카드에 태그와 단계가 가득하다.
- 로그인하지 않은 사람이나 북마크가 없는 사람에게 홈이 빈 화면으로 보인다.
- 이모지가 하나라도 들어간다.
- v2에서 북마크하거나 진행 단계를 바꾼 내용이 지금 사이트와 어긋난다(같은 계정, 같은 데이터여야 한다).

## 3. 제약

- **디자인 기준:** madia-design 스킬과, 그 위에 적어 둔 프로젝트 우선 규칙(이모지 금지, 다크 모드 유지, 분야 색 유지, 대시보드 밀도, 접근성 유지).
- **토큰:** 다듬은 `index.html`과 같은 값을 쓴다. Pretendard Variable, 행간 1.4, 자간 -0.025em, `#111111`/`#707070`/`#F7F7FB`/`#E5E5EC`, 굵기 500/600(가격만 700), 모서리 8/12/16px와 알약형, 간격 2·4·6·8·12·16·20·24·32·40·48, 전환 0.3초, 컨테이너 1280px, 카드 패딩 24px(좁은 화면 16px).
- **데이터:** `static/cnh_data_bundle.js`(`window.CNH_STATIC_DATA`)와 `static/data_adapter.js`(`CivilData.getInitialData / loadAll / getCached / calcDaysLeft`)를 그대로 쓴다.
- **사용자 데이터:** 북마크와 진행 단계는 localStorage `cnh-saved`, `cnh-tracked`와 Supabase `user_saved(user_id, ids, tracked)`를 지금 사이트와 **같은 키와 같은 형식**으로 읽고 쓴다. 진행 단계 계산은 `static/tracker_core.js`(`CNHTracker`)를 그대로 쓴다.
- **로그인:** Supabase Google 로그인, `flowType: 'pkce'`. 돌아오는 주소가 `location.pathname` 기준이라 `/v2.html`이 된다. Supabase 대시보드의 Auth → URL Configuration → Redirect URLs에 `https://civil-news-hub.vercel.app/v2.html`(그리고 로컬 확인용 주소)이 없으면 로그인이 막힌다. 사용자가 직접 추가해야 한다. 로그인하지 않아도 v2의 나머지 기능은 동작해야 한다.
- **배포:** `.vercelignore`가 허용 목록 방식이라 `!v2.html`을 추가해야 Vercel에 올라간다. push는 사용자가 따로 지시할 때만 한다.
- **테스트:** `python -m pytest -q tests`(이모지 검사 포함)와 `node --test tests/tracker_core.test.js tests/sync_guard.test.js`가 통과해야 한다.

## 4. 덜어내기 규칙 (모든 탭)

1. 한 화면에는 **주인공 목록 하나**만 둔다. 나머지는 접거나 다른 탭으로 보낸다.
2. 목록은 처음에 **5~6개**만 보여 주고 "더 보기"로 펼친다.
3. 목록 한 줄(또는 카드 한 장)에는 **제목, 출처, D-day**만 둔다. 태그, 전형 단계, 요약문은 눌렀을 때 열리는 상세 패널로 옮긴다.
4. 필터는 **한 줄**로 줄이고, 자주 안 쓰는 정렬은 메뉴 안에 넣는다.
5. 로그인하지 않았거나 관심 분야를 고르지 않은 사람에게는 홈 맨 위에 **"관심 분야 고르기"**를 보여 주고, 그 전에는 전체 마감 임박 3개를 대신 보여 준다.

## 5. 접근 방식

| 방법 | 내용 | 결과 |
|---|---|---|
| **1. 새 페이지 `v2.html` (선택)** | 같은 데이터와 로그인을 연결한 새 페이지 | 실제 데이터로 비교할 수 있고 지금 사이트에 영향이 없다. 작업량이 가장 많다. |
| 2. 정적 시안 | 데이터를 직접 써 넣은 HTML | 빠르지만 쓸 수 없고 버려진다. |
| 3. 브랜치에서 `index.html` 재작성 | 완성되면 교체 | 다듬은 버전과 충돌하고, 미리 보려면 push가 필요하다. |

사용자가 1번을 골랐다. 이유: "지금 사이트는 놔두고 새로"라는 요구에 맞고, 정보량은 실제 데이터로 써 봐야 판단할 수 있다.

## 6. 화면 설계

**공통 틀 (Claude의 결정)**
- **PC와 모바일은 별도 화면(DOM)으로 만든다. (사용자 결정)** 이유: PC 이용자는 평소 쓰던 PC용 웹사이트 형태를, 모바일 이용자는 익숙한 모바일 전용 화면을 기대하기 때문이다. 한 화면을 접어서 양쪽을 맞추지 않는다. 지금 사이트의 `#ca` / `#m` 구조와 같다. 어느 쪽을 보여 줄지는 지금 `index.html`의 `isPhoneDevice()`와 같은 규칙으로 정한다: 스마트폰 기기이면 모바일, 아니면 창 너비 600px 이하일 때만 모바일. 두 화면은 데이터와 사용자 상태(북마크, 진행 단계, 관심 분야)를 함께 쓰고, 마크업과 CSS는 각자 가진다. CSS는 지금처럼 `#v2pc`, `#v2m` 같은 범위로 나눠 서로 영향을 주지 않게 한다.
- **PC:** 상단 GNB 1단 80px에 로고, 탭 6개, 검색, 로그인을 둔다. 실시간 트렌딩 줄은 뺀다(규칙 1). 키워드는 뉴스 탭 안으로 옮긴다. 상세 정보는 오른쪽 패널로 연다.
  - **PC 홈 (2026-11-23 사용자 피드백으로 다시 만듦):** 처음 만든 "같은 크기 카드 두 칸 + 아래 카드" 배치는 "모바일 화면을 옆으로 놓은 것 같다"는 평을 받았다. 그래서 PC 웹사이트에서 익숙한 배치로 바꾼다. 넓은 본문 칸(제목, **표로 된** 마감·발표 일정 최대 5줄, 관심 분야 필터 줄과 새 소식 표 최대 5줄)과 오른쪽 320px 사이드(내 저장함 개수와 로그인, 월간 달력, 오늘의 토목 뉴스 5개)로 나눈다. 표는 열 머리(남은 날·구분·제목·기관·날짜)를 두고, 줄 위에 마우스를 올리면 강조하며, 줄 아무 곳이나 누르면 원문이 열린다. 달력에는 저장한 일정이 있는 날에 점을 찍고, 날짜를 누르면 그날 일정이 나온다. 창 너비가 1200px 미만이면 사이드를 본문 아래 두 칸으로 옮긴다. 모바일 홈은 그대로 둔다.
- **모바일:** 상단 바와 가로 탭 줄, 하단 탭바를 두고 1열 목록으로 보여 준다. 상세 정보는 바텀시트로 연다. 홈의 세 묶음 순서와 개수는 PC와 같다.
- 라우팅은 지금처럼 `#home`, `#news`, `#contests`, `#jobs`, `#jbnu`, `#my` 해시를 쓴다.

**홈 (A안, 위에서부터)**
1. 제목 "오늘 챙길 것 N개"와 날짜.
2. **마감·발표 일정:** 북마크와 진행 중인 항목의 다음 날짜(마감일 또는 결과 발표일)를 가까운 순으로 3개 보여 주고 "전체 N개" 링크를 둔다. 비어 있으면 전체 마감 임박 3개를 "마감 임박"이라는 제목으로 보여 준다.
3. **내 관심 분야 새 소식:** 고른 분야 칩, 그리고 마지막 방문 이후 새로 들어온 공모전·채용·기사 3개. 분야를 아직 고르지 않았으면 분야 고르기 칩만 보여 준다.
4. **오늘의 토목 뉴스:** 제목만 3줄 보여 주고 "뉴스 탭" 링크를 둔다.

**나머지 탭 (규칙 4를 적용한 모습)**
- **뉴스:** 분야 필터 한 줄과 기사 목록(제목, 언론사, 시각). 첫 기사만 큰 사진으로 보여 준다. 같은 보도자료 묶음은 상세 패널에서 연다.
- **공모전:** 분야 필터 한 줄과 마감순 목록(제목, 주최, D-day). 포스터는 상세 패널에서 본다.
- **채용:** 구분(인턴/신입/경력) 필터 한 줄과 마감순 목록(공고명, 기관, D-day). 전형 단계와 태그는 상세 패널로 옮긴다.
- **전북대:** 교내 공모전과 알바를 각 5개씩 보여 주고 "더 보기"를 둔다.
- **마이:** 진행 카드 목록(지금 마이페이지와 같은 단계 계산)과 관심 분야 설정을 둔다.

**관심 분야 (데이터마다 분류가 달라서 세 묶음으로 고른다)**

| 묶음 | 고를 수 있는 값 | 데이터 필드 |
|---|---|---|
| 뉴스 분야 | 토목 종합, 도로·교량·철도, 수자원·하천·항만, 터널·지반·안전, 스마트건설·정책 | `news.articles[].category_id` (`CivilData.mapNewsCat`) |
| 공모전 종류 | 토목, 전북대, 컴퓨터공학 | `contests.contests[].track` (civil / campus / it) |
| 채용 기관 | 공기업·공공기관, 건설·민간기업, 설계·엔지니어링 | `jobs.jobs[].category_name` |

어느 묶음에서도 고르지 않은 항목은 "새 소식"에 넣지 않는다. 묶음 하나를 통째로 비워 두면 그 종류의 항목은 새 소식에 나오지 않는다.

**"새 소식"의 기준:** 공고에는 수집 시각이 없으므로 시각이 아니라 **"이 브라우저에서 아직 홈에 띄운 적 없는 항목"**으로 판단한다. 정렬은 뉴스 `iso_date`, 공모전 `start_date`, 채용 `period` 앞 날짜 기준으로 최신순이다. 처음 방문하면 본 항목이 없으므로 이 정렬의 위 3개가 나온다.

**새로 저장하는 값 (이 브라우저에만)**
- `cnh-v2-interests`: `{ news: [...], contests: [...], jobs: [...] }`
- `cnh-v2-seen`: 홈의 새 소식에 한 번 띄운 항목 id 배열. 최근 500개만 유지한다.

**2·3단계 구현 결과 (2026-11-23, Claude의 결정 포함)**
- **PC 탭 화면 = "목록 + 오른쪽 상세" 두 칸.** 왼쪽은 필터 한 줄과 목록(한 줄에 D-day, 제목, 출처만), 오른쪽 440px 칸은 고른 항목의 상세(사진·포스터, 원문 보기, 저장, 도전 목록에 추가, 표로 정리한 정보, 전형 단계, 같은 소식 기사 묶음). 처음에는 첫 항목이 열려 있다. 채용 사이트의 공고 목록과 상세처럼 PC에서 익숙한 배치이고, 목록을 누를 때마다 페이지가 바뀌지 않는다. 1200px 미만에서는 상세 칸을 360px로 줄인다.
- **모바일 탭 화면 = 목록 + 아래에서 올라오는 상세 시트.** 필터는 가로로 밀리는 한 줄. 뉴스는 첫 기사만 큰 사진.
- **처음 보여 주는 줄 수:** PC 10줄, 모바일 6줄, "더 보기"로 같은 수만큼 더. (규칙 2의 5~6개를 모바일에 적용하고, PC는 한 줄 높이가 낮고 오른쪽 상세가 있어 10줄로 정함)
- **전북대:** 교내 공모전 · 알바 · SW 프로그램을 한 줄 필터로 바꿔 가며 본다(규칙 1, 한 화면에 목록 하나). 처음 설계의 "두 목록을 5개씩 함께"에서 바꿈.
- **채용:** 채용 형태(전체·인턴·신입·경력) 칩과 기관 구분 선택 상자를 한 줄에. 기관 채용 페이지 링크는 목록 아래 접힌 칸.
- **마이:** 진행 중인 도전 · 저장한 항목 · 내 기록을 한 줄 필터로 바꿔 본다. 진행 카드는 지금 사이트와 같은 단계 계산과 버튼(제출했어요, 수상·합격, 미선정, 되돌리기, 삭제 확인). 계정, 관심 분야, 화면 밝기는 PC 오른쪽 칸 / 모바일 아래쪽. 도전 추가는 공모전·채용 상세의 "도전 목록에 추가"로 한다(지금 사이트의 팝업 대신).
- **검색:** PC는 상단 검색창, 모바일은 상단 바의 돋보기 → 검색 화면. 뉴스 제목·언론사, 공모전·채용·알바의 제목과 기관에서 찾고, 공고는 지금 지원할 수 있는 것만. 많이 나온 키워드(실시간 트렌딩)는 뉴스 탭(PC)과 검색 화면에 둔다.
- **주소:** `#news`, `#contests`, `#jobs`, `#jbnu`, `#my`, `#saved`(모바일 하단 "저장"), `#search=검색어`.
- 코드: 목록 계산은 `static/v2_core.js`(테스트 있음), 화면은 `static/v2_pages.js`.

## 7. 빌더에게 맡기는 것

- 컴포넌트를 어떻게 나눌지, CSS와 JS를 `v2.html` 안에 둘지 `static/v2.css`, `static/v2.js`로 분리할지.
- 북마크·진행 단계 동기화 코드는 `index.html` 안에 있다. v2에서는 이 코드를 **복사해서** 쓴다(지금 파일을 건드리지 않기 위해). 나중에 v2로 교체할 때 정리한다.
- 빈 상태, 로딩, 오류 문구.

## 8. 진행 순서
