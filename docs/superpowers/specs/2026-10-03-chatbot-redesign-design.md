# 토목 뉴스 AI 챗봇 리디자인 설계

- 날짜: 2026-10-03
- 대상: `goofy-borg` 작업본의 새 "모던 UI" (`static/index.html`, 아직 커밋 전)
- 상태: 사용자 검토 대기

## 1. 목적

사람들은 뉴스 목록에서 기사를 **클릭하지 않고 제목과 본문 일부만 훑어봐요.** 그러다 궁금한 게 생기면 챗봇에게 물어봐요.

- "이 기사는 무슨 내용이야?" → 기사 **요약**
- "이 단어는 무슨 뜻이야?" → **용어 설명**

**성공 기준**
- 챗봇 창을 연 채로 기사 목록을 보고, 스크롤하고, 제목을 읽으면서 질문을 입력할 수 있어요. 데스크톱과 모바일 모두 해당돼요.
- 요약을 받은 다음 기사 이름을 다시 말하지 않고 "'국책사업'이 뭐야?"라고 물어도 같은 기사 맥락으로 답해요.
- 챗봇이 새 모던 UI의 색, 글꼴, 다크 모드와 한 몸처럼 보여요.

## 2. 결정 사항 (브레인스토밍에서 확정)

| 항목 | 결정 |
|---|---|
| 질문 방식 | 사용자가 채팅창에 직접 입력해요 (카드 버튼이나 드래그 없음) |
| 창 모양 | 오른쪽 아래에 **떠 있는 작은 창**. 화면을 어둡게 하지 않고, 접을 수 있어요 |
| 분위기 | 예전 챗봇 구조(어두운 헤더, 말풍선, 로봇 버튼) 유지 + **새 UI 색 토큰**으로 다시 칠하기 |
| 모바일 | **절반 높이 시트**. 위로 끌면 85%로 커지고, 뒤 화면은 계속 스크롤할 수 있어요 |
| 대화 맥락 | 마지막 기사를 **기억**하고, "○○ 기사에 대해 대화 중 ✕" 표시를 보여줘요 |
| 적용 위치 | 원본 `goofy-borg`의 새 모던 UI |

## 3. 현재 상태

- 마지막 커밋(v1.1.31)의 예전 화면은 `static/chatbot.js`(1,082줄, Tailwind와 Lucide 사용)를 불러와요.
- 새 모던 UI(`static/index.html`, 커밋 전)는 **챗봇을 불러오지 않아요.** Tailwind와 Lucide도 쓰지 않아요.
  - 색과 글꼴: CSS 변수(`--bg --surface --surface-2 --ink --muted --line --accent --accent-soft --shadow --r`), IBM Plex Sans KR
  - 다크 모드: `prefers-color-scheme` 또는 `:root[data-theme]`
  - 화면 구성: 데스크톱 `#ca`와 모바일 `#m`이 따로 있고, `max-width:600px` 기준으로 바뀌어요
  - 기존 겹침 요소의 z-index: 헤더 20, 하단 탭바 30, scrim 40, drawer와 sheet 50, toast 60
- `app.py`의 `/api/chat` 프록시(Gemini)와 `/api/chat/status`는 그대로 써요.

## 4. 설계

### 4-1. 파일 구성

- **기존 `static/chatbot.js`는 건드리지 않고 새 파일 두 개를 만들어요.** 그러면 예전 화면(v1.1.31)도 깨지지 않고, 지금 진행 중인 새 UI 작업과도 겹치지 않아요.
  - `static/cnh_chat_core.js`: DOM을 쓰지 않는 순수 로직이에요. 단어 나누기, 기사 점수 매기기, 맥락 고르기, 용어 질문 판별, 프롬프트 만들기가 들어 있어요. 브라우저에서는 `window.CNHChatCore`, Node에서는 `module.exports`로 쓸 수 있어서 `node --test`로 테스트해요.
  - `static/cnh_chatbot.js`: 화면 주입, 열기·접기·닫기, 모바일 시트 끌기, 메시지 그리기, API 호출을 담당해요. 자기 전용 스타일을 `<style id="cnh-chatbot-style">`로 주입하고, 모든 선택자는 `#cnhChatbot` 아래로 한정해요. 아이콘은 인라인 SVG로 넣어요.
  - 색은 새 UI의 CSS 변수만 써요. 그러면 다크 모드가 저절로 따라와요.
- 새 UI는 `index.html`과 `static/index.html` 두 곳에 같은 내용으로 있어요. 루트 `/` 주소는 `index.html`을 먼저 보여줘요. **두 파일 모두에** `</body>` 앞(화면 고르기 스크립트 뒤)에 `<script>` 두 줄(core → chatbot 순서)만 추가해요. 이 작업은 다른 사람이 새 UI를 편집하는 중이 아닐 때, 맨 마지막에 해요.

### 4-2. 화면: 데스크톱 (601px 이상)

- **로봇 버튼**: 오른쪽 아래(`right:24px; bottom:24px`), 64px 크기에 안전모 로봇 이미지(`static/ai_robot_avatar.png`)를 써요. 둥실 애니메이션과 초록 온라인 점은 유지해요. z-index는 35예요(탭바 위, scrim 아래).
- **창**: `width:400px; height:min(560px, calc(100vh - 120px))`, `right:24px; bottom:24px`, `border-radius:14px`, `background:var(--surface)`, `border:1px solid var(--line)`, `box-shadow:var(--shadow)` 위에 그림자를 하나 더 얹어요. z-index는 35예요.
  - **헤더**: `background:var(--ink)`, 글자색 `var(--bg)`. 헤더 안 아이콘은 `var(--accent)` 사각형에 "AI" 글자를 넣어요. 제목 "토목 뉴스 AI 브리핑", 부제 "기사 기반 Q&A"를 넣고, 버튼은 [🔑 API 키] [↺ 초기화] [— 접기] [✕ 닫기] 순서예요.
  - **추천 질문 칩**: 가로 스크롤이에요. 예: "오늘 주요 기사 요약", "어려운 용어 풀어줘", "도로·철도 소식만", "이번 주 지하안전 이슈"
  - **메시지**: 내 말풍선은 `background:var(--ink); color:var(--bg)`, AI 말풍선은 `background:var(--surface-2); color:var(--ink)`이에요. AI 답 아래에는 근거 기사 칩(언론사와 제목)을 붙이고, 누르면 원문이 새 창에서 열려요.
  - **맥락 표시** (4-4 참고): 입력창 바로 위에 붙어요. `background:var(--accent-soft); color:var(--accent)` 알약 모양이에요.
  - **입력창**: `background:var(--surface-2)`, 보내기 버튼은 `background:var(--accent)`예요.
- **비모달 동작**: scrim도 없고 스크롤 잠금도 없어요. 창 밖을 클릭해도 닫히지 않아요. 기사 목록을 그대로 스크롤하고 클릭할 수 있어요. ESC는 입력창에 포커스가 있을 때만 창을 접어요.
- **접기(—)와 닫기(✕)**: 둘 다 창을 숨기고 로봇 버튼을 다시 보여줘요. 접기는 대화와 맥락을 그대로 두고, 닫기는 대화는 남기되 맥락 표시를 지워요. 대화 기록은 지금처럼 `sessionStorage`에 저장해요.
- 새 UI의 drawer(z 50)나 scrim(z 40)이 열리면 챗봇(z 35)이 그 아래로 가려져요. 이건 의도된 동작이에요.
- **폭이 601~760px일 때**: 데스크톱 화면에도 하단 탭바(`#ca .bottom-bar`, 약 58px)가 생겨요. 이때는 로봇 버튼과 창의 `bottom`을 `calc(58px + env(safe-area-inset-bottom) + 16px)`로 올려서 탭바와 겹치지 않게 해요. 창 높이는 `calc(100vh - 160px)`까지로 줄여요.

### 4-3. 화면: 모바일 (600px 이하, `#m`)

- **로봇 버튼**: `bottom: calc(58px + env(safe-area-inset-bottom) + 12px); right:16px`, 56px 크기예요. 탭바 위에 떠 있어요. 챗봇은 `#m` 바깥에 붙어서 `#m`에만 정의된 `--tab-h`(58px)를 읽을 수 없어요. 그래서 58px를 챗봇 스타일 안에 `--cnh-tab-h`로 따로 둬요.
- **시트**: `position:fixed; left:50%; transform:translateX(-50%); width:100%; max-width:440px; bottom:0`, `border-radius:20px 20px 0 0`. 새 UI의 `#m .sheet`와 같은 모양이에요.
  - 높이는 두 단계예요. **기본 50dvh**, 펼치면 **85dvh**예요. 위쪽 손잡이(36×4px 막대)를 끌어서 바꿔요.
    - 위로 40px 넘게 끌면 → 85%
    - 85%에서 아래로 40px 넘게 끌면 → 50%
    - 50%에서 아래로 80px 넘게 끌면 → 접기
    - 손잡이를 탭하면 50%와 85% 사이를 오가요.
  - 시트가 탭바를 덮어요(z 35 > 30). 시트가 열려 있는 동안 탭바는 시트 아래에 있어요.
  - scrim도 없고 `body` 스크롤 잠금도 없어요. 시트 위쪽 화면에서 기사를 계속 스크롤할 수 있어요. 메시지 영역에는 `overscroll-behavior:contain`을 줘서 스크롤이 뒤 화면으로 넘어가지 않게 해요.
  - 입력창에 포커스가 가서 키보드가 올라오면 `visualViewport`를 기준으로 시트 아래쪽을 맞춰요.
- 데스크톱과 모바일 화면이 바뀔 때(`matchMedia('(max-width:600px)')`의 change 이벤트) 창 상태(열림·접힘)와 대화는 그대로 두고 배치만 바꿔요.

### 4-4. 대화 맥락: 기사 기억

**상태**: `activeArticle = { id, title, publisher, link } | null`. `sessionStorage`에 대화와 함께 저장해요.

**질문 처리 순서** (`handleUserMessage`)
1. `rankArticles(articles, query)`로 점수를 매겨요. 질문 전체가 제목에 들어 있으면 +20, 단어마다 제목 +6, snippet +3, 관련 기사 제목 +2, 분야명 +2예요. "기사", "요약해줘", "뭐야" 같은 흔한 단어는 빼고 세요.
2. **새 기사로 바꾸는 조건**: 1등 점수가 **9점 이상**이고, 1등이 비교 대상보다 **1.5배 이상** 높아야 해요. 비교 대상은 2등 점수와 지금 기억 중인 기사 점수 중 큰 값이에요. 9점은 회사명처럼 제목의 핵심 단어 하나가 맞았을 때의 점수예요(제목 6 + snippet 3). 조건을 만족하면 그 기사를 `activeArticle`로 삼아요.
3. 조건에 맞지 않고 `activeArticle`이 있으면 → **기억해 둔 기사를 첫 번째 근거로** 넣고, 나머지 자리는 검색 결과로 채워요(최대 4건).
4. 조건에 맞지 않고 `activeArticle`도 없으면 → 지금처럼 검색 결과 상위 4건을 써요.
5. Gemini에 보내는 요청에 **최근 대화 4턴**(`history`)을 같이 보내요. 그래야 "그 단어"나 "아까 기사" 같은 말을 알아들어요.

**맥락 표시**: `activeArticle`이 있으면 입력창 위에 "💬 {제목 앞 18자}… 기사에 대해 대화 중 ✕"를 보여줘요. ✕를 누르면 `activeArticle = null`이 돼요. 초기화(↺)를 눌러도 같이 지워져요.

**기사 데이터**: 새 UI의 `NEWS`는 스크립트 안의 지역 변수라서 챗봇이 꺼내 쓸 수 없어요. 그래서 챗봇이 직접 `/api/news`를 불러오고, 실패하면 `./data/news.json`을 불러와요(지금의 `ensureArticlesLoaded`와 같아요). 원본 기사 항목에는 `id, title, link, publisher, category_name, snippet, published_at, relative_date, related_articles`가 있어요. `summary`나 `body`는 **없어요.** 그래서 서버로 보낼 때는 `{title, media: publisher, published_at, summary: [snippet, 관련 기사 제목 최대 3개]}` 모양으로 바꿔서 보내요. 서버 프롬프트가 이미 `summary`와 `media`를 읽기 때문이에요.

### 4-5. 서버 (`app.py` `/api/chat`)

- 요청 본문에 `history: [{role, text}]`(선택)를 받아서 Gemini `contents`에 이전 대화로 넣어요. 값이 없으면 지금과 똑같이 동작해요.
- 시스템 지시문에 두 가지를 추가해요.
  - "기사 요약은 3줄 이내 불릿으로 써요."
  - "용어 질문에는 기사 속 맥락을 살려서 쉬운 말로 1~2문장으로 답하고, 예를 하나 들어요."
- 브라우저에서 Gemini를 직접 부르는 경로에도 같은 지시문과 history를 넣어요. 모델은 예전 코드에 고정돼 있던 `gemini-1.5-flash` 대신 `/api/chat/status`가 알려주는 모델을 쓰고, 알 수 없으면 `gemini-flash-latest`를 써요.

### 4-6. 키가 없을 때 (로컬 요약 모드)

- 지금처럼 기사 데이터만으로 "팩트 브리핑 카드"를 보여줘요.
- 용어 질문처럼 보이면("뜻", "뭐야", "의미"가 들어간 질문) 이렇게 안내해요. "단어 뜻 풀이는 AI 연결이 필요해요. 🔑 버튼에서 키를 넣으면 쓸 수 있어요." 그리고 `activeArticle`의 요약을 같이 보여줘요.

## 5. 오류 처리

- 기사 데이터를 불러오지 못하면 "기사 목록을 불러오지 못했어요"라는 메시지 말풍선과 [다시 시도] 버튼을 보여줘요.
- Gemini 한도 초과(429)나 키 오류는 지금의 메시지를 그대로 쓰고, AI 말풍선 대신 경고 스타일(`--warn`)로 보여줘요.
- 답을 기다리는 동안에는 보내기 버튼을 막고, 점 세 개 로딩 표시를 보여줘요(지금과 같아요).

## 6. 확인 방법

자동 테스트가 없는 정적 페이지라서 **실제 브라우저에서 확인**해요(Flask `python app.py` → `http://localhost:8000`).

1. 데스크톱 1440×900, 라이트와 다크 모드: 창을 연 채로 뒤 기사 목록을 스크롤하고 기사 제목 링크를 클릭할 수 있는지
2. "대우건설 기사 요약해줘" → "'국책사업'이 뭐야?": 두 번째 답이 같은 기사 맥락인지, 맥락 표시가 보이는지, ✕를 누르면 사라지는지
3. 다른 기사 제목으로 질문하면 맥락 표시가 그 기사로 바뀌는지
4. 모바일 390×844: 시트가 50%로 열리는지, 위쪽 화면이 스크롤되는지, 끌어서 85%와 접기가 되는지, 탭바와 겹침이 없는지, 키보드가 올라와도 입력창이 가려지지 않는지
5. 창 폭을 600px 경계에서 오가도 대화가 유지되는지
6. 키가 없을 때: 요약 카드와 용어 안내가 나오는지
7. 새 UI의 drawer나 sheet를 열었을 때 챗봇이 그 아래로 가려지는지

## 7. 범위 밖

- 기사 카드의 "요약" 버튼, 단어 드래그 질문, 입력 자동완성 (나중에 추가할 후보)
- 예전 화면(v1.1.31)의 챗봇 개선 (`static/chatbot.js`는 그대로 남겨 둬요)
- `antigravity-handoff/clone`과 `new-app` 동기화
