# 마이페이지 · 제출 진행 상황 추적 설계

- 작성일: 2026-11-19
- 상태: 사용자 검토 대기

## 1. 왜 만드나

북마크만으로는 "이 공모전 냈던가?", "그 채용 결과 나왔나?"를 기억하기 어렵다. 북마크해 둔 공모전·채용 중 **실제로 도전하는 것**을 골라, 내 제출 여부와 그 이후의 흐름(심사, 결과)을 한 화면에서 추적한다. 로그인하면 PC와 모바일에서 같은 기록을 본다.

## 2. 목표 / 목표 아님 / 실패 조건

> **규칙: 웹페이지 어디에도 이모지를 쓰지 않는다.** 상태·결과·버튼은 글자와 기존 SVG 아이콘, 색 배지로만 표시한다.

**목표**
- 테마 버튼 자리에 마이페이지 진입 버튼을 둔다(PC 헤더, 모바일 하단 탭).
- 마이페이지에 ① 진행 중인 도전 ② 내 기록(결과가 나온 도전) ③ 북마크 전체 ④ 테마 설정을 모은다.
- ＋ 팝업에서 공모전·채용(북마크 여부와 무관)을 골라 진행 카드로 올리고, 5가지 상태로 추적한다.
- 공고가 수집 목록에서 사라져도 카드 정보가 남는다.

**목표 아님**
- 알림(텔레그램·푸시) 보내기
- 뉴스·전북대 알바·SW 프로그램 추적 (공모전·채용만)
- 결과(수상/합격 여부)를 자동으로 알아내기

**실패 조건** (기술적으로 동작해도 실패로 본다)
- 공고가 마감·삭제된 뒤 카드가 비거나 사라진다.
- 제출하지 않았는데 "심사중"으로 표시된다.
- 로그인한 사용자가 다른 기기에서 다른 진행 상태를 본다.
- 기존 북마크 기능이 깨진다.

## 3. 상태와 흐름

```
미제출 ──[제출했어요]──▶ 제출완료 ──(마감 지남·자동)──▶ 심사중 ──[수상·합격 / 미선정]──▶ 결과발표
   │                        ▲                              │
   │                        └──────[되돌리기]──────────────┘ (실수 정정)
   └──(마감 지남·자동)──▶ 마감(미제출)
```

| 상태 | 어떻게 되나 | 카드 표시 |
|---|---|---|
| 미제출 | ＋로 추가한 직후 | 마감 D-day, **[제출했어요]** 버튼 |
| 제출완료 | 사용자가 [제출했어요] 클릭 (제출일 기록) | "11/19 제출", [되돌리기] |
| 심사중 | 제출완료 상태에서 마감일이 지나면 **자동** | "심사 N일째". 발표일을 알면 "발표 예정 12/7"<br>발표일이 지나면 "결과 나왔을 거예요. 확인해 보세요" 강조 |
| 결과발표 | 사용자가 [수상·합격] 또는 [미선정] 클릭 | **내 기록으로 이동**. 결과 배지, [되돌리기] |
| 마감(미제출) | 미제출 상태에서 마감일이 지나면 **자동** | 회색 처리, [삭제] |

- 저장하는 건 사용자가 직접 한 행동(제출일, 결과)뿐이다. **심사중·마감(미제출)은 저장하지 않고 화면을 그릴 때마다 마감일과 오늘 날짜로 계산한다.** 그래야 기기 시계나 접속 시점과 무관하게 같은 결과가 나온다.
- 마감일을 모르는 공고(상시 모집 등)는 자동 전환하지 않는다. 제출완료 상태로 두고, 사용자가 결과를 직접 누른다.
- 채용 카드는 심사중일 때 공고의 전형 단계(`서류 → 면접 → 건강검진`)를 참고용으로 보여 준다. 단계별 체크는 하지 않는다.

## 4. 화면

**진입**
- PC: 헤더의 테마 버튼(`#theme`)을 **사람 아이콘 "마이페이지"** 버튼으로 바꾼다 → `#my`
- 모바일: 하단 탭의 "테마"(`#m-theme`)를 **"마이"**로 바꾼다 → 모바일 `my` 화면
- 기존 북마크 버튼(서랍)은 그대로 둔다. 빠르게 보는 용도.

**마이페이지 (PC)**
```
┌ 마이페이지 ─────────────────────────────────────────────┐
│ 홍길동 계정에 저장 중  [로그아웃]        테마 [라이트 / 다크] │
├ 진행 중인 도전 ─────────────────────────────────────────┤
│ ┌─────────────┐ ┌─────────────┐ ┌ ─ ─ ─ ─ ─ ─ ┐       │
│ │공모전 · D-5   │ │채용 · 심사 3일째│                    │
│ │서울관광 프롬프톤│ │수자원공사 …    │ │      ＋      │       │
│ │●━━○━━○━━○   │ │●━━●━━●━━○   │   북마크에서 추가       │
│ │[제출했어요]    │ │서류→면접→검진  │ └ ─ ─ ─ ─ ─ ─ ┘       │
│ └─────────────┘ └─────────────┘                        │
├ 내 기록 · 수상 2 · 미선정 3 ───────────────────────────────────┤
│ [수상] 2026 JBNU 학생설계전공 공모전 · 11/02 제출 · 12/07 결과   │
│ [미선정] 한국수자원공사 경력사원 · 10/20 지원 · 11/15 결과          │
├ 북마크 (12) ────────────────────────────────────────────┤
│ 공모전 · …  /  채용 · …  /  뉴스 · …                       │
└─────────────────────────────────────────────────────────┘
```
- 진행 카드 정렬: 확인이 필요한 것(발표일 지남, 마감 임박 미제출) → 진행 중 → 마감(미제출) 순.
- **내 기록**: 수상·합격 / 미선정를 누르는 순간 카드가 "진행 중인 도전"에서 빠져 **내 기록**으로 옮겨진다. 맨 위에 수상·합격·미선정 개수 요약, 목록은 결과 기록일 최신순. 각 줄에 종류·제목·기관·제출일·결과일·원문 링크, [되돌리기](심사중으로 복귀), 삭제(휴지통 아이콘).
- 내 기록에는 **제출하고 결과까지 나온 것만** 간다. 마감(미제출)은 진행 중 영역 맨 아래에 회색으로 남고, 직접 지운다.
- 진행 막대: 미제출 · 제출완료 · 심사중 · 결과발표 4칸. 마감(미제출)은 막대 대신 회색 표시.
- 모바일은 같은 구성을 한 열로 쌓는다.

**＋ 누르면 팝업**이 뜬다. 탭 3개:
```
┌ 도전 추가 ─────────────────────── X ┐
│ [공모전]  [채용]  [북마크]              │
│ 대구 로컬AI그라운드 · D-20    [＋ 추가] │
│ 서울관광 프롬프톤 · D-12      [＋ 추가] │
│ 제주 AI·빅데이터 · D-3        [추가됨] │
└──────────────────────────────────┘
```
- 공모전 탭: 모집 중인 공모전 전체 / 채용 탭: 모집 중인 채용 전체 / 북마크 탭: 북마크 중 공모전·채용만 (뉴스·알바·SW 제외)
- 정렬: **D-day가 많이 남은 순**(마감이 먼 것이 위). 마감일 없는 상시 공고는 맨 아래.
- 이미 추가한 공고는 "추가됨"로 표시해 중복을 막는다. 누르면 카드가 미제출 상태로 생기고 팝업은 열린 채 유지해 여러 개를 연달아 추가할 수 있다.
- 진행 카드는 북마크와 독립이다. 북마크를 해제해도 카드는 남고, 카드는 삭제(휴지통 아이콘)로만 지운다.
- 삭제(휴지통 아이콘) 삭제는 모든 카드(진행 중·내 기록)에 있다. 누르면 사이트 스타일의 확인창 **"정말 삭제할까요?" [취소] [삭제]**를 띄우고, [삭제]를 눌러야 지운다.

**로그인 안 했을 때**: 기능은 그대로 쓸 수 있고 이 브라우저에만 저장된다. 상단에 로그인 안내 칸을 둔다(북마크와 같은 문구).

## 5. 데이터

**카드 1장 (브라우저가 ＋ 클릭 시 공고에서 복사해 만든다)**
```json
{
  "id": "공고 id",
  "kind": "contest | job",
  "title": "…", "org": "…", "link": "https://…",
  "deadline": "2026-11-30",
  "resultDate": "2026-12-07 또는 null",
  "steps": ["서류전형", "면접전형"],
  "addedAt": "2026-11-19",
  "submittedAt": "2026-11-20 또는 null",
  "result": "win | lose | null",
  "resultAt": "… 또는 null"
}
```
- 공고 정보(제목·기관·링크·마감·발표일·전형)는 **추가하는 순간의 복사본**이다. 이후 공고가 목록에서 사라져도 카드는 그대로 남는다.
- 같은 공고가 아직 목록에 있고 마감일·발표일이 바뀌었으면, 화면을 그릴 때 최신 값으로 갱신해 저장한다(공고 정정 대응).

**저장 위치**
- 로그인: Supabase `user_saved` 표에 열 `tracked jsonb default '[]'` 추가. 북마크와 같은 행, 같은 RLS(본인 행만).
- 비로그인: localStorage `cnh-tracked`.
- 로그인 순간 합치기: 북마크와 같은 방식. 같은 id가 양쪽에 있으면 **진행이 더 앞선 쪽**을 남긴다(결과 > 제출 > 미제출).
- 용량: 카드 1장 약 0.5KB.

**SQL (사용자가 SQL Editor에서 1회 실행)**
```sql
alter table public.user_saved add column if not exists tracked jsonb not null default '[]'::jsonb;
```

## 6. 수집 쪽 변경: 결과 발표일 뽑기 (jcloud)

- 공모전 데이터에 `result_date`(YYYY-MM-DD, 못 찾으면 비움)를 추가한다.
- 찾는 곳:
  1. 포스터 OCR(`contest_poster_reader.py`, Gemini flash-lite) 프롬프트에 "결과/수상자/당선작 발표일" 항목을 추가한다.
  2. 본문 글에서 `결과|수상자|당선작|합격자|최종 … 발표 … 날짜` 패턴을 정규식으로 찾는다.
- 여러 개면(1차 발표, 최종 발표) **가장 늦은 날짜(최종 발표)**를 쓴다.
- 채용은 이번 범위에서 발표일을 뽑지 않는다(공고 구조가 제각각이라 효과 대비 비용이 크다).
- 원문 27건 확인 결과: 본문에서 발표가 언급된 곳은 6건이고, 대부분의 날짜는 포스터나 첨부파일에 있다. 추출률은 구현 후 실제로 측정해서 보고한다.

## 7. 검토한 방식

| | A. 별도 페이지 `#my` (**선택**) | B. 오른쪽 서랍 |
|---|---|---|
| 장점 | 카드를 여러 열로 넓게. PC·모바일 같은 구조 | 보던 화면 유지 |
| 단점 | 다른 탭으로 이동하는 느낌 | 폭이 좁아 진행 막대·버튼이 답답함 |

사용자가 A를 골랐다. 진행 카드에 막대, 버튼, 전형 단계가 모두 들어가야 해서 넓은 화면이 맞다.

## 8. 사용자가 정한 것
- 4단계(미제출 → 제출완료 → 심사중 → 결과발표) + 마감(미제출)
- 제출은 직접 기록하고, 마감이 지나면 자동으로 심사중
- 결과 발표일은 공고에서 뽑고, 결과(수상·합격 / 미선정)는 직접 기록
- 공고 정보를 카드에 복사해 Supabase(로그인) 또는 브라우저(비로그인)에 저장
- 결과 기록, 되돌리기, 채용 전형 단계 표시, 로그인 동기화, 모바일 적용, 테마 설정을 마이페이지로 이동
- 형태: 별도 페이지(A)
- ＋ 팝업: 공모전·채용·북마크 탭, 북마크와 무관하게 추가, D-day 많이 남은 순 정렬
- 진행 카드는 북마크 해제와 무관하게 남고, 삭제(휴지통 아이콘) + "정말 삭제할까요?" 확인 후 지움
- 결과가 나온 도전은 별도 "내 기록"으로 모아서 봄

## 9. 만드는 사람이 정할 것 (내가 정한 것, 검토 요청)
- 진행 카드 정렬 순서 (4장)
- 로그인 합치기 충돌 규칙: 진행이 더 앞선 쪽 우선 (5장)
- 추적 대상: 공모전·채용만. 알바·SW 프로그램은 제외
- 공고 정정 시 마감일·발표일 자동 갱신 (5장)
- 발표일이 여러 개면 가장 늦은 날짜 사용 (6장)
- 마감 시각: 마감일 23:59가 지나야 "지남"으로 본다 (`deadline_time` 무시)
- 아이콘·색: 기존 디자인 토큰 재사용
- 마감(미제출) 카드에도 [제출했어요]를 둔다. 제출해 놓고 버튼만 깜빡한 경우를 위해서이며, 누르면 바로 심사중으로 간다
