# v2 1단계 (공통 로직 + PC 홈 + 모바일 홈) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 새 페이지 `v2.html`에서 PC 화면과 모바일 화면이 각각 "오늘 챙길 것 → 내 관심 분야 새 소식 → 오늘의 토목 뉴스" 홈을 실제 데이터와 사용자 북마크로 보여 준다.

**Architecture:** 홈에 들어갈 목록 계산은 화면 없는 순수 함수 모듈 `static/v2_core.js`(node 테스트)에 둔다. 북마크·진행 단계·로그인 동기화는 `index.html`의 공용 스크립트를 `static/v2_state.js`로 복사하고, 기존 `sync_guard` 테스트가 두 사본을 모두 검사하게 한다. `v2.html`은 PC DOM(`#v2pc`)과 모바일 DOM(`#v2m`)을 따로 가지며, 같은 데이터와 같은 상태를 각자의 마크업으로 그린다.

**Tech Stack:** 순수 HTML/CSS/JS(빌드 없음), `node --test`, pytest(이모지 검사), Supabase JS 2.45.4(CDN), Pretendard Variable 1.3.9(CDN), 미리보기용 headless Chrome.

**Spec:** `docs/superpowers/specs/2026-11-23-v2-redesign-design.md`

## Global Constraints

- `index.html`, `contests.html`, `jobs.html`, `mobile.html`, `static/data_adapter.js`, `static/tracker_core.js`, `static/cnh_data_bundle.js`는 수정하지 않는다.
- 이모지 금지. 아이콘은 인라인 SVG, 상태는 텍스트와 색 배지. `tests/test_no_emoji.py`가 `*.html`, `static/**/*.js`를 검사한다.
- 토큰(라이트): `--bg:#F7F7FB; --surface:#FFFFFF; --surface-2:#EFEFF4; --ink:#111111; --muted:#707070; --line:#E5E5EC; --accent:#D9480F; --accent-soft:#FFE8DB`.
- 토큰(다크, `prefers-color-scheme:dark`와 `:root[data-theme="dark"]` 두 곳): `--bg:#0E0E10; --surface:#18181B; --surface-2:#232327; --ink:#F2F2F2; --muted:#A0A0A6; --line:#2C2C31; --accent:#FF7A2E; --accent-soft:#3A2012`.
- 서체: `"Pretendard Variable",Pretendard,-apple-system,BlinkMacSystemFont,"Apple SD Gothic Neo","Malgun Gothic",system-ui,sans-serif`, CSS `https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css`.
- 전역 `line-height:1.4; letter-spacing:-.025em`. 굵기는 500(기본)과 600(제목·강조)만 쓴다.
- 글자 크기 12/14/15/16/18/20/24/32px. 12px는 날짜·배지 전용. 모서리 8/12/16px와 `999px`. 간격 2·4·6·8·12·16·20·24·32·40·48px. 전환 `.3s`.
- PC: 컨테이너 `max-width:1280px`, 좌우 패딩 20px, GNB 1단 높이 80px, 카드·섹션 패딩 24px, 섹션 모서리 16px.
- 모바일: 앱 열 `max-width:440px` 가운데 정렬, 상단 바 52px, 탭 줄 44px, 하단 탭바 58px + `env(safe-area-inset-bottom)`, 좌우 패딩 20px.
- 화면 선택 규칙은 `index.html`의 `isPhoneDevice()`와 같다(iPad·안드로이드 태블릿은 PC, 스마트폰은 모바일, 그 외 창 너비 600px 이하만 모바일).
- localStorage 키: 기존 `cnh-saved`, `cnh-tracked`, `cnh-theme`를 같은 형식으로 공유. 새 키는 `cnh-v2-interests`, `cnh-v2-seen`만 쓴다.
- 오늘 날짜는 KST(`new Date(Date.now() + 9*3600000).toISOString().slice(0,10)`).
- push 금지. 커밋은 사용자가 지시할 때만 한다(각 Task의 Commit 단계는 사용자 승인 후 실행).

## Review Focus

1. 처음 온 사람(북마크·진행 카드·관심 분야 없음)도 홈이 비지 않아야 한다. "마감 임박" 3개와 관심 분야 고르기가 보여야 한다. → Task 1 `urgentFallback` 테스트, Task 5 시드 없는 캡처.
2. 북마크했지만 수집 데이터에서 사라진 공고는 조용히 빠지고, 진행 카드는 카드에 저장된 제목·날짜로 계속 나와야 한다. → Task 1 테스트.
3. 마감일이나 발표일이 비어 있거나 지난 항목은 일정에 나오지 않아야 한다(D-99나 음수 D-day가 나오면 안 된다). → Task 1 테스트.
4. 관심 분야의 새 항목을 모두 본 뒤에는 예전 항목을 다시 "새 소식"으로 내보내지 않고 "새 소식이 없어요"를 보여야 한다. → Task 2 테스트, Task 5 문구.
5. localStorage가 막혀 있거나 값이 깨진 JSON이어도 화면이 그려져야 한다. → Task 2 `readJSON` 테스트.

### Task 1: 홈 일정 계산 (`static/v2_core.js`)

**Files:**
- Create: `static/v2_core.js`
- Test: `tests/v2_core.test.js`

**Interfaces:**
- Consumes: `static/tracker_core.js`의 `stageOf(card, today)`, `visible(cards)`, `startFromPeriod(period)` (node에서는 `require('./tracker_core.js')`, 브라우저에서는 `window.CNHTracker`).
- Produces: 모듈은 `tracker_core.js`와 같은 UMD 형태(node `module.exports`, 브라우저 `window.CNHv2`)로 아래를 내보낸다.
  - `ddayLabel(date: 'YYYY-MM-DD', today: 'YYYY-MM-DD') -> string`: 같은 날이면 `'D-DAY'`, 아니면 `'D-' + 남은 일수`.
  - `dateLabel(date: 'YYYY-MM-DD') -> string`: `'MM.DD'`.
  - `scheduleItems(src: {saved: string[], tracked: Card[], contests, jobs, albas}, today) -> ScheduleItem[]`
  - `urgentFallback(src: {contests, jobs}, today, n = 3) -> ScheduleItem[]`
  - `ScheduleItem = { id: string, kind: 'contest'|'job'|'alba', title: string, org: string, date: 'YYYY-MM-DD', what: 'deadline'|'result', label: string }`
  - 필드 매핑: contest는 `title`/`org`/`deadline`, job은 `role`/`co`/`deadline`, alba는 `title`/`where`/`deadline_date` (모두 `CivilData.getInitialData()`의 `CONTESTS`, `JOBS`, `ALBA` 형태).

- [ ] **Step 1: 실패하는 테스트 작성** (`tests/v2_core.test.js`, `node:test` + `node:assert/strict`, `T = '2026-11-23'`)
  - `ddayLabel('2026-11-23', T) === 'D-DAY'`, `ddayLabel('2026-11-28', T) === 'D-5'`, `dateLabel('2026-12-02') === '12.02'`.
  - `scheduleItems`: 진행 카드 `makeCard('contest', {id:'c1', title:'A', deadline:'2026-11-28'}, T)`(미제출)는 `{id:'c1', what:'deadline', label:'D-5'}`로 나온다.
  - 제출 후 마감이 지나고 `resultDate:'2026-12-02'`인 카드는 `{what:'result', date:'2026-12-02', label:'12.02'}`로 나온다.
  - `result`가 있는 카드, 마감이 지난 미제출 카드, `deleted:true` 카드는 나오지 않는다.
  - 북마크 `saved:['j1']`이고 `jobs:[{id:'j1', role:'R', co:'K', deadline:'2026-11-23'}]`이면 `{id:'j1', kind:'job', title:'R', org:'K', label:'D-DAY'}`로 나온다.
  - 북마크 id가 데이터에 없으면 빠진다(오류 없음). 같은 id가 진행 카드와 북마크에 모두 있으면 한 번만 나온다(진행 카드 우선).
  - `deadline:''`인 항목, 어제 마감인 북마크는 나오지 않는다.
  - 결과는 `date` 오름차순, 같은 날이면 `title` 오름차순으로 정렬된다.
  - `urgentFallback({contests:[…4개], jobs:[…]}, T)`는 오늘 이후 마감인 공모전·채용 중 마감이 가까운 3개를 반환하고, 지난 것과 날짜 없는 것은 뺀다.

- Produces (같은 `CNHv2` 객체에 추가):
  - `INTEREST_GROUPS`: 아래 값 그대로.
    ```js
    [
      { key: 'news', title: '뉴스 분야', options: [['general','토목 종합'],['road','도로·교량·철도'],['water','수자원·하천·항만'],['tunnel','터널·지반·안전'],['smart','스마트건설·정책']] },

    ]
    ```
  - `hasInterests(interests) -> boolean`: 세 묶음 중 하나라도 비어 있지 않으면 `true`.
  - `freshItems(src: {news, contests, jobs}, interests: {news: string[], contests: string[], jobs: string[]}, seen: string[], today, n = 3) -> FreshItem[]`
  - `FreshItem = { id: string, kind: 'news'|'contest'|'job', title: string, meta: string, badge: '새 기사'|'새 공고' }`. meta는 news `src`, contest `ddayLabel(deadline)`(마감일 없으면 `org`), job `co`.

- [ ] **Step 1: 실패하는 테스트 추가**

  - 순서: 종류마다 최신순(news는 배열 순서 그대로, contest는 `startDate` 내림차순, job은 `startFromPeriod(period)` 내림차순, 날짜 없는 것은 맨 뒤)으로 줄 세운 뒤 news → contest → job 순으로 하나씩 번갈아 n개를 뽑는다.
  - `seen`에 있는 id는 빠진다. 해당하는 항목을 모두 봤으면 `[]`를 반환한다(예전 항목을 다시 채우지 않는다).
  - `rememberSeen(['a','b'], ['b','c'], 3)`는 `['a','b','c']`, `rememberSeen(['a','b','c'], ['d'], 3)`는 `['b','c','d']`.
  - `readJSON`: 정상 JSON이면 그 값, `getItem`이 throw하면 fallback, 깨진 JSON이면 fallback, fallback이 배열인데 값이 배열이 아니면 fallback.
  - `isPhone`: iPhone UA는 `true`, `iPad` UA는 `false`, `platform:'MacIntel', maxTouchPoints:5`는 `false`, `Android` + `Mobile`은 `true`, `Android`만 있으면 `false`, 데스크톱 UA에 `width:600`이면 `true`, `width:601`이면 `false`.

- [ ] **Step 1: 홈 렌더링 구현** (PC는 `#pc-home`, 모바일은 `#m-home`에 각자의 마크업으로)
  1. 제목 `오늘 챙길 것 {N}개`(N = 일정 개수), 부제 `{M}월 {D}일 {요일}요일 · 저장한 항목 기준`.
  2. **마감·발표 일정:** `scheduleItems` 앞 3개. 줄마다 왼쪽 알약 배지(`label`, `D-DAY`는 `--accent` 바탕 흰 글자), 제목(한 줄 말줄임), 오른쪽 종류(`공모전`/`채용`/`알바`, `what==='result'`이면 `발표`). 섹션 오른쪽 링크 `전체 {N}개`는 `index.html#my`로 간다. 일정이 0개면 섹션 제목을 `마감 임박`으로 바꾸고 `urgentFallback` 3개를 같은 줄 모양으로 보여 준다.
  3. **내 관심 분야 새 소식:** `hasInterests`가 `false`이면 `INTEREST_GROUPS`를 묶음 제목과 칩으로 보여 주고 안내 문구 `관심 있는 것을 고르면 새 소식을 모아 드려요`를 단다. 칩을 누르면 `cnh-v2-interests`에 저장하고 다시 그린다. `true`이면 고른 칩만 한 줄로 보여 주고(오른쪽 링크 `분야 바꾸기`는 전체 칩 편집을 연다) `freshItems` 3개를 보여 준 뒤, 보여 준 id를 `rememberSeen`으로 `cnh-v2-seen`에 저장한다. 결과가 `[]`이면 `새 소식이 없어요`를 보여 준다.
  4. **오늘의 토목 뉴스:** `data.NEWS` 앞 3개의 제목만, 링크는 원문(`target="_blank" rel="noopener noreferrer"`). 섹션 링크 `뉴스 탭`은 `index.html#news`로 간다.
  - 새 소식은 **페이지를 열 때 한 번** 계산해 `V2.fresh`에 두고 그 자리에서 `cnh-v2-seen`에 기록한다. 이후 북마크 변경 등으로 `render()`가 다시 불려도 `V2.fresh`를 그대로 쓰고, 관심 분야를 바꿨을 때만 다시 계산한다. 그래야 방금 보여 준 항목이 같은 방문 중에 사라지지 않는다.
  - 모든 텍스트는 `esc()`를 거친다.
